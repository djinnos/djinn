# Memory-sustainability fixture contract

`manifest.json` is the versioned contract consumed by the workload driver and
evaluator. Generated bytes are deliberately **not** checked into Git. Generate
into a writable scratch directory (the worker image permits `/var/tmp`):

```sh
perl server/docs/operational/memory-sustainability/fixtures/generate.pl \
  --profile smoke --output-dir /var/tmp/memory-sustainability-smoke --validate

perl server/docs/operational/memory-sustainability/fixtures/generate.pl \
  --profile production --output-dir /var/tmp/memory-sustainability-production --validate
```

Use `--validate-only` to inspect an already-generated directory without
rewriting it. Every validation failure exits nonzero and names the violated
contract: graph schema/count/range, board eligibility/count, artifact chunk
count/contiguous index/size, total bytes, transport checksum, or report
checksum.

## Production profile

The deterministic `ste6-production-v1` profile creates:

- a 71,303,168-byte canonical graph fixture blob (68 MiB), whose header records
  65,220 graph nodes and 277,200 edges; this falls within the required 65–70
  MiB range;
- 10,000 `BoardHealthMismatchCandidate` projection rows. Each is an open task
  with three reopens and `requires task_create`, so the landed role-signal
  logic expects `planner` while task dispatch selects `worker`;
- an artifact spool with exactly 600 zero-based contiguous 256 KiB chunks,
  totaling exactly 157,286,400 bytes (150 MiB), ordered chunk SHA-256 values,
  and a SHA-256 over their exact concatenation.

The graph fixture intentionally does not implement a second
`RepoGraphGenerationRepository` or a second graph serializer. Its header names
the existing canonical `RepoGraphArtifact` publication seam and the opaque
suffix supplies the deterministic persisted-blob memory pressure. Production
serialization remains owned by `djinn-graph`; the fixture contract supplies the
count and byte-size workload to the driver.

## Reproducibility

The generator uses only the stable profile seed and a specified xorshift32 byte
stream. `manifest.json` stores expected SHA-256 values for the graph bytes,
board JSONL, artifact transport, and artifact manifest. Generation and
validation both compare observed hashes to those values, so a seed, formatter,
count, range, chunk ordering, payload byte, or checksum drift fails before the
fixture can be used.

`smoke` exercises the identical schemas and validators with 256 graph nodes,
1,024 edges, a 1 MiB blob, 40 eligible board tasks, and six contiguous 256 KiB
chunks (1.5 MiB total). It is the routine worker check; it is not a substitute
for the external production-equivalent run.
