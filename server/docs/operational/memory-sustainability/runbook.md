# Memory-sustainability staging, rollout, and rollback runbook

> **Release boundary:** the commands below collect the external, production-equivalent staging gate. The gate is two hours (`7200` seconds) with default five-minute board ticks and 100 sequential alternating 200/304 requests. Checked-in smoke evidence is not release evidence.
>
> **Prohibited:** do not run a contract/drop migration in this epic. Contract/drop is outside this epic and remains prohibited until release owners have observed **zero legacy telemetry** for the approved observation period **and** the rollback window is closed.

## 1. Set the operator-owned parameters and evidence location

Examples never assume a cluster, namespace, release, or service name. Set these values for the approved staging target; preserve the exact values in the evidence checklist.

```sh
export CLUSTER='<approved-cluster>'
export NAMESPACE='<approved-namespace>'
export RELEASE='<helm-release>'
export PROJECT_ID='<approved-project-id>'
export SERVER_SELECTOR='app.kubernetes.io/component=server'
export CANDIDATE_IMAGE='registry.example/djinn-server@sha256:<candidate-digest>'
export PRECHANGE_IMAGE='registry.example/djinn-server@sha256:<pre-change-digest>'
export EVIDENCE_ROOT='/durable/release-evidence/memory-sustainability/<change-id>'
export CANDIDATE_RUN="$EVIDENCE_ROOT/candidate"
export DIAGNOSTIC_RUN="$EVIDENCE_ROOT/pre-change-diagnostic"
mkdir -p "$CANDIDATE_RUN" "$DIAGNOSTIC_RUN"
```

`$EVIDENCE_ROOT` must be durable release storage, not an ephemeral pod filesystem. Restrict it because raw output can identify infrastructure, but never place bearer tokens in it.

## 2. Generate and retain the deterministic fixture

Generate production bytes once per image run; retain the generator stdout, report, manifest copy, and SHA-256 values. The output path is supplied to the operator-installed fixture inspection/install commands below.

```sh
export FIXTURE_DIR="$CANDIDATE_RUN/fixtures"
perl server/docs/operational/memory-sustainability/fixtures/generate.pl \
  --profile production --output-dir "$FIXTURE_DIR" --validate \
  | tee "$CANDIDATE_RUN/fixture-generation.json"
cp server/docs/operational/memory-sustainability/fixtures/manifest.json "$CANDIDATE_RUN/fixture-manifest.json"
sha256sum "$CANDIDATE_RUN/fixture-manifest.json" "$FIXTURE_DIR/fixture-report.json" \
  | tee "$CANDIDATE_RUN/fixture-checksums.sha256"
```

The production fixture is `ste6-production-v1`: 65,220 nodes, 277,200 edges, a 68 MiB canonical blob, 10,000 eligible board rows, and a 600-chunk/150 MiB artifact. Do not substitute generated bytes from an unrecorded profile.

## 3. Run a pre-change diagnostic (non-gating)

Deploy or select the approved pre-change image in an isolated production-equivalent staging target. Use the same 4 GiB cgroup and fixture profile. Record the resolved digest before running. The driver requires operator commands that call the **landed** graph install, board scan, generation inspection, restart inspection, and fixture inspection interfaces; their JSON shapes are shown in `driver/README.md`.

```bash
set -o pipefail
export IMAGE_ID="$PRECHANGE_IMAGE"
export RUN_DIR="$DIAGNOSTIC_RUN"
# Populate these commands with target-specific wrappers; do not put credentials in flags.
export DJINN_METRICS_URL='https://<metrics-host>/metrics'
export DJINN_GALAXY_URL="https://<server-host>/api/projects/$PROJECT_ID/code-graph/galaxy"
export DJINN_GALAXY_TOKEN="$(cat /secure/path/galaxy-token)"
export DJINN_GRAPH_INSTALL_COMMAND='<landed graph install command using $FIXTURE_DIR>'
export DJINN_BOARD_SCAN_COMMAND='<landed persisted board scan command emitting {"pages":40}>'
export DJINN_GRAPH_GENERATION_COMMAND='<landed generation inspection emitting {"generation":"..."}>'
export DJINN_RESTART_COUNTER_COMMAND='<target restart counter emitting {"restarts":0}>'
export DJINN_FIXTURE_INSPECTION_COMMAND='<fixture inspection emitting observed seed/checksums/identities>'
printf '%s\n' "$IMAGE_ID" > "$RUN_DIR/image-digest.txt"
perl server/docs/operational/memory-sustainability/driver/memory_workload.pl \
  --profile production --output "$RUN_DIR/driver-raw.jsonl" \
  2>&1 | tee "$RUN_DIR/driver.log"
```

Keep diagnostic raw output separately. It is rendered for comparison but cannot turn a failing candidate into a pass or a passing candidate into a failure.

## 4. Candidate image preflight and collection

First deploy/select exactly `$CANDIDATE_IMAGE` using the normal release mechanism, then capture immutable identity and preflight facts. The driver itself verifies an exact 4 GiB cgroup, cgroup event readability, no resident graph at T0, fixture identity/checksums, required allocator/graph metrics, a 40-page board pass, and initial 200 then 304 responses.

```bash
set -o pipefail
export IMAGE_ID="$CANDIDATE_IMAGE"
export RUN_DIR="$CANDIDATE_RUN"
printf '%s\n' "$IMAGE_ID" > "$RUN_DIR/image-digest.txt"
date --iso-8601=seconds | tee "$RUN_DIR/started-at.txt"
kubectl --context "$CLUSTER" -n "$NAMESPACE" get pods -l "$SERVER_SELECTOR" -o wide \
  | tee "$RUN_DIR/server-pods-before.txt"
kubectl --context "$CLUSTER" -n "$NAMESPACE" get pods -l "$SERVER_SELECTOR" \
  -o jsonpath='{range .items[*]}{.metadata.name}{" "}{.status.containerStatuses[*].restartCount}{"\n"}{end}' \
  | tee "$RUN_DIR/restart-baseline.txt"
perl server/docs/operational/memory-sustainability/driver/memory_workload.pl \
  --profile production --output "$RUN_DIR/driver-raw.jsonl" \
  2>&1 | tee "$RUN_DIR/driver.log"
date --iso-8601=seconds | tee "$RUN_DIR/finished-at.txt"
sha256sum "$RUN_DIR/driver-raw.jsonl" "$RUN_DIR/driver.log" \
  | tee "$RUN_DIR/raw-checksums.sha256"
```

The unmodified driver defaults are the required protocol: **T0** after 30 minutes idle with no graph; graph install and its warm/server peak; **T1** after 15 minutes quiescent with the same graph resident; then a two-hour burst with 100 sequential alternating 200/304 requests scheduled across the full interval, including the final request at burst end. Board scans remain independently scheduled every five minutes during that interval. **T2** is collected no sooner than five minutes after the actual final galaxy response completes; the raw `galaxy_request` and `t2_timing` records provide high-resolution completion/delay evidence. Do not use duration or request overrides for staging evidence.

Use the checked-in `evaluator/adapt_driver_jsonl.pl` adapter; do not hand-edit a wrapper. It validates finalized successful JSONL, preserves the driver run ID and supplied image digest in every derived record, and records SHA-256 references to the source JSONL and fixture manifest.

## 5. Evaluate and retain machine-readable evidence

Create `$EVIDENCE_ROOT/evaluator-input.json` with mandatory `candidate` and optional `pre_change_diagnostic` runs that conform to `evaluator/raw-schema.json`. Do not hand-edit measurements after collection.

```bash
set -o pipefail
perl server/docs/operational/memory-sustainability/evaluator/adapt_driver_jsonl.pl \
  --candidate-raw "$CANDIDATE_RUN/driver-raw.jsonl" --candidate-image "$CANDIDATE_IMAGE" \
  --candidate-fixture-manifest "$CANDIDATE_RUN/fixture-manifest.json" \
  --diagnostic-raw "$DIAGNOSTIC_RUN/driver-raw.jsonl" --diagnostic-image "$PRECHANGE_IMAGE" \
  --diagnostic-fixture-manifest "$CANDIDATE_RUN/fixture-manifest.json" \
  --output "$EVIDENCE_ROOT/evaluator-input.json" \
  2>&1 | tee "$EVIDENCE_ROOT/adapter.log"
perl server/docs/operational/memory-sustainability/evaluator/evaluate.pl \
  --input "$EVIDENCE_ROOT/evaluator-input.json" \
  --json-out "$EVIDENCE_ROOT/evaluation.json" \
  --report-out "$EVIDENCE_ROOT/evaluation.md" \
  2>&1 | tee "$EVIDENCE_ROOT/evaluator.log"
sha256sum "$EVIDENCE_ROOT/evaluator-input.json" "$EVIDENCE_ROOT/evaluation.json" \
  "$EVIDENCE_ROOT/evaluation.md" "$EVIDENCE_ROOT/adapter.log" "$EVIDENCE_ROOT/evaluator.log" \
  | tee "$EVIDENCE_ROOT/evaluation-checksums.sha256"
```

A zero exit and `candidate.status: "pass"` are both required. Preserve `evaluation.json` as the machine-readable decision and `evaluation.md` as its exact human rendering. Required gates are: server and warm peak <= 3.5 GiB; route RSS delta <= 32 MiB; every board pass <= 120000 ms; no OOM/restart delta; a single graph generation from install through T2; T2 RSS <= `max(128 MiB, 10% of T1)` above T1; and T2 jemalloc retained <= 256 MiB above T1.

Complete [evidence-checklist.md](evidence-checklist.md), attach the raw paths/checksums and evaluation result to the change record, and obtain reviewer and release approver names before advancing rollout.

## 6. Deployment order and symmetric rollback

Use only the landed compatibility and retention interfaces. Each pre-contract step has an immediate rollback to the prior compatible state.

| Forward step | Required observation before next step | Symmetric rollback |
|---|---|---|
| 1. **Expand** schema/compatibility release | Expand succeeds; legacy path remains readable/writable; no contract action | Roll back application to previous compatible version; leave expanded schema intact |
| 2. **Dual-read server** | Server reads canonical and legacy-compatible data; record legacy telemetry | Roll back server to the prior legacy reader/writer |
| 3. **Warmer** | Warm publication has stable generation identity and artifact serving remains healthy | Disable/roll back warmer to prior publication behavior; retain readable compatibility data |
| 4. **UI** | Galaxy UI sees explicit landed REST outcomes and no route regression | Roll UI back to prior compatible client |
| 5. **Retention dry-run** | Candidate/skip/retry metrics and logs are expected; no deletion | `helm upgrade "$RELEASE" deploy/helm/djinn --reuse-values --set-string graphRetention.mode=off --wait` (or restore the previous values) |
| 6. **Retention delete** | Approved dry-run evidence, stream-pin safety, and retention observations | Immediately set `graphRetention.mode=off`; deleted generations are not reconstructed by migration |
| 7. **Eventual contract** | **Not in this epic.** Only after zero legacy telemetry and closed rollback window | No contract command is authorized here |

For steps 5 and 6, the landed Helm surface is exactly `graphRetention.mode` (`off`, `dry_run`, or `delete`) and `graphRetention.historyN` (1–64). Start dry-run explicitly and retain rendered/release evidence:

```sh
helm upgrade "$RELEASE" deploy/helm/djinn --namespace "$NAMESPACE" --reuse-values \
  --set-string graphRetention.mode=dry_run --set graphRetention.historyN=3 --wait \
  | tee "$EVIDENCE_ROOT/retention-dry-run-helm.txt"
# Only after review of dry-run evidence:
helm upgrade "$RELEASE" deploy/helm/djinn --namespace "$NAMESPACE" --reuse-values \
  --set-string graphRetention.mode=delete --set graphRetention.historyN=3 --wait \
  | tee "$EVIDENCE_ROOT/retention-delete-helm.txt"
```

Never interpret retention delete as permission to contract/drop compatibility storage. Record the rollback-window close and zero-legacy-telemetry proof in the checklist; until both are recorded, stop at compatible operation.

## 7. Rerun and failure handling

* Driver failure, interruption, OOM, restart change, graph replacement, malformed cgroup/metrics, request mismatch, or preflight failure: preserve `<output>.partial`, its log, timestamps, pod identity, and checksums. Do not rename it as a passing raw file.
* Evaluator failure: preserve input, JSON result, Markdown result, evaluator log, and raw references. Mark the candidate failed; do not edit/reuse the evidence to obtain a pass.
* Correct the target/image/configuration only through the approved deployment process, choose a new `$EVIDENCE_ROOT` run identity, repeat fixture generation and the entire T0/install/T1/burst/T2 sequence, then evaluate again.
* At any rollout step, select that row's rollback action, record the decision and operator in the checklist, and stop progression. Rollback remains available through every pre-contract step.
